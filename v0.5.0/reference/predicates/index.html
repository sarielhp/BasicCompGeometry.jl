Kernels and predicates

See Kernels and numerical scope for arithmetic policies and their limits. Turn predicates such as turn_sign and is_left_turn are in the primitive reference. Circle-boundary comparisons belong to Extras.

BasicCompGeometry.AbstractKernel — Type
AbstractKernel

Arithmetic policy for geometric predicates. Ordinary calls use FloatingKernel(). Algorithms accepting kernel= must forward that same object to every predicate; they must not reconstruct a default internally.

Custom kernels implement the kernel-first predicate methods they support, for example turn_sign(kernel, p, q, r) and compare_xy(kernel, p, q). Unsupported methods fail rather than silently using floating-point arithmetic. Kernels select predicate arithmetic, not the storage type of geometric objects. Persistent structures should store the concrete kernel type with their state; cached predicates from different kernels must not be mixed.

source
BasicCompGeometry.ExactKernel — Type
ExactKernel()

Exact predicates on integer, rational, and finite binary floating-point inputs. Integers are widened to BigInt before arithmetic. Rational and floating-point inputs use Rational{BigInt}. A floating-point input means its stored binary value, not the decimal value that may have been intended by the caller.

This kernel does not provide exact geometric constructions: an intersection previously rounded to floating point remains a rounded input. No epsilon or fixed-precision BigFloat calculation is used to decide signs.

source
BasicCompGeometry.FloatingKernel — Type
FloatingKernel()
FloatingKernel(Float32)

Ordinary floating-point predicate arithmetic, using Float64 by default. Input coordinates are converted before arithmetic; integer overflow in the original coordinate type is therefore avoided, but rounding and floating-point overflow can still affect predicate results. This is not a certified filter.

source
BasicCompGeometry.compare_distance — Method
compare_distance(p, q, radius; kernel=FloatingKernel())

Compare the distance between points with a nonnegative radius, returning -1, 0, or 1. Squaring occurs inside the selected kernel, without taking a square root. Equality includes tangency when this predicate is used for disk tests.

source
BasicCompGeometry.compare_right_arc_to_point — Method
compare_right_arc_to_point(center, q, radius; kernel=FloatingKernel())

Compare the right circular boundary at q.y with q.x, returning -1, 0, or 1. The height must be in the circle's arc domain; the radius must be nonnegative.

source
BasicCompGeometry.compare_right_arcs — Method
compare_right_arcs(p, q, height, radius; kernel=FloatingKernel())

Compare the right circular boundaries p.x + sqrt(radius^2-(height-p.y)^2) and the corresponding expression for q, returning -1, 0, or 1. Both circles have the same nonnegative radius. The height must be in both arc domains. The exact kernel compares radicals algebraically, without constructing them.

source
BasicCompGeometry.compare_squared_distance — Method
compare_squared_distance(p, q, squared; kernel=FloatingKernel())

Compare the squared distance between points with squared, returning -1, 0, or 1. Supply an exact squared threshold when using ExactKernel; the kernel cannot undo rounding or overflow in a threshold computed by the caller.

source
BasicCompGeometry.compare_xy — Method
compare_xy(p, q; kernel=FloatingKernel())

Compare two 2D points lexicographically, returning -1, 0, or 1.
