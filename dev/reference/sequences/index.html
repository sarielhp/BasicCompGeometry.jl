BasicCompGeometry.AbsPntSeq — Type
AbsPntSeq{D, T}

Abstract supertype for all representations of a sequence of points (polygonal chain or polygon) in D dimensions with coordinate type T. Subtypes must implement the AbsFMS interface (dist and size) and provide access to vertices.

BasicCompGeometry.AnyDim — Type
AnyDim

Marker in the dimension slot of AbsPntSeq{D, T} for a sequence whose dimension is known only at run time, such as MatVecPntSeq. Code compiled for such a sequence serves every dimension. Use dim to get the dimension; functions that use D as a number (for example to build a Point{D, T}) do not accept these sequences.

BasicCompGeometry.ColumnPoint — Type
ColumnPoint{T, M}

Column j of a matrix, as a read-only point (AbstractVector{T}) that shares the matrix's memory: reading it reads the matrix, nothing is copied, and writing through it (p[i] = x) is an error. The points of a MatVecPntSeq are of this type. Arithmetic on them (p - q, 2p) returns a new Vector{T}; copy(p) and collect(p) give a Vector{T} that no longer shares memory.

ColumnPoint(mat, j) checks that mat has a column j and 1-based indices.

BasicCompGeometry.GPntSeq — Type
GPntSeq{D, T, P}

A sequence of points of type P in D dimensions with coordinate type T: a polygonal curve or a classical polygon. The points are stored sequentially in the pnts field. P must be a concrete AbstractVector{T} type; PntSeq{D, T} is the case P = Point{D, T}. P may also be a virtual point type (AbsVirtualPoint, such as VPoint), points known only through distances: the sequence is then a GPntSeq{AnyDim, Float64, P}, and functions that need coordinates do not accept it.

Choosing the point type: static points (Point{D, T}) have their loops unrolled and compiled for each D, and creating one costs nothing. Points whose length is known only at run time (Vector{T}) are compiled once for all dimensions and run plain vectorized loops, but each new point is a heap allocation. Measured on distance kernels (FrechetDist's example_higher/point_types.jl, AMD Ryzen 7 5700G, Julia 1.13): static points are faster up to D = 16, the two are close for D = 32 to 96, and from D = 128 on Vector points compute distances 2 to 4.5 times faster. Static code also takes seconds to compile at D = 1000, and minutes for a large algorithm at D = 6000. Creating points stays faster with static points up to about D = 512.

D is either the dimension or AnyDim, for a dimension known only at run time (dim(P) is then the length of the first point). Points whose length is not part of their type are checked on construction and by push!: each must have D coordinates, or, for AnyDim, as many as the first point. Static points need no check.

GPntSeq is a subtype of AbsPntSeq{D, T}, meaning it can be treated as a finite metric space where its vertices are the points and the distance is Euclidean.

BasicCompGeometry.MatPntSeq — Type
MatPntSeq(mat::AbstractMatrix{T}; copy::Bool = false)
MatPntSeq{D, T, M, V}

A sequence of points stored in a D × N matrix: column j is point j, read as a Point{D, T}. D = size(mat, 1).

By default the sequence shares the matrix's memory; nothing is copied.

  • Changes to the matrix are seen by the sequence: after mat[1, 2] = 5.0, P[2][1] == 5.0.
  • Changes through the sequence are written into the matrix: P[j] = p, translate! and scale! modify mat.
  • The same holds for a view or an adjoint: the sequence then shares the memory of the view's parent array.
  • Points read from the sequence are copies (P[j] is a static vector built from column j), so they cannot be written through; changing a point later does not change the sequence.
  • The number of points is fixed: push!, pop! and empty! are not defined.

copy = true copies the matrix into a new dense Matrix{T} first. The sequence is then independent: later changes to mat are not seen, and changes through the sequence do not reach mat. Use it when the matrix will be modified afterwards, or when the sequence will be translated or scaled and the matrix must stay as it was. Matrix(P) always returns a copy.

Since D is read from the matrix at run time, this constructor is not type-stable; pass the result to a function (a function barrier) before using it in a hot loop.

BasicCompGeometry.MatVecPntSeq — Type
MatVecPntSeq(mat::AbstractMatrix{T}; copy::Bool = false)

A sequence of points stored in a D × N matrix, like MatPntSeq, whose points are read-only views of the columns (ColumnPoint) instead of static vectors. The dimension is size(mat, 1), read at run time: the type is AbsPntSeq{AnyDim, T} (see AnyDim), so the constructor is type-stable and code compiled for one dimension serves all of them. This is the representation for high dimensions: loops over the coordinates are not unrolled, and reading a point copies nothing. In low dimensions MatPntSeq is faster (see the guide's "Static or Vector points"). Functions written for any point type accept this sequence (among them dist, dist_sq and convex_comb on its points, and geom_length, prefix_lengths and split_edges on the sequence); those that need Point{D, T} do not.

Memory is shared with the matrix exactly as for MatPntSeq: changes to the matrix are seen by the sequence, and P[j] = p, translate! and scale! write into the matrix. Points cannot be written through, and the number of points is fixed. copy = true first copies the matrix into a new dense Matrix{T}, making the sequence independent of it.

BasicCompGeometry.hausdorff_simplify — Method
hausdorff_simplify(P, w)

Simplify the pntseq P using a greedy approach based on the Hausdorff distance. The resulting pntseq vertices are a subset of the original vertices. For every segment [v_i, v_{i+1}] in the simplification, the Hausdorff distance to the original subcurve it replaces is at most w. Returns (simplified_pnt_seq, vertex_indices).
