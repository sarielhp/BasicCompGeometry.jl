Metric spaces

BasicCompGeometry.MetricSpace — Module
MetricSpace

The MetricSpace module provides a framework for working with abstract finite metric spaces (FMS). It is designed to decouple algorithms that operate on metric spaces (like clustering or greedy permutations) from the underlying representation of the points and the distance function.

Core Concepts

  • Abstract Finite Metric Space (AbsFMS): The base type for all metric spaces in this module.
  • Indices as Points: Points in a finite metric space are represented by integers 1:n.
  • Interface: Any subtype of AbsFMS must implement Base.size and dist.

Supported Space Types

  1. PointsSpace: Defined by a collection of points of any type that supports dist(p1, p2).
  2. MPointsSpace: Defined by a matrix where columns represent points. Uses Euclidean distance.
  3. AbsPntSeq: Any point sequence can be treated as an AbsFMS.
  4. PermutMetric: A wrapper that allows reordering or subsetting an existing metric space via a permutation vector.
  5. SpherePMetric: A specialized space where distances are defined as angles relative to a base point (useful for spherical geometry or directional data).

Algorithms

  • greedy_permutation_naive: Implements Gonzalez's algorithm for k-center clustering and generating hierarchical orderings of points.

BasicCompGeometry.MetricSpace.SpherePMetric — Type
SpherePMetric{MetricType} <: AbsFMS

A specialized metric space where distances are defined as the angle formed at a base point b_point between two points i and j.

Given base point B and points X, Y, the distance is the angle ∠XBY calculated via the Law of Cosines using the distances in the underlying metric space m.

Fields

  • m::MetricType: The underlying metric space.
  • I::Vector{Int}: Indices of points included in this spherical space.
  • D::Vector{Float64}: Precomputed distances from each point in I to b_point.

BasicCompGeometry.HilbertSpace — Type
HilbertSpace(items, dist2; max_bytes = typemax(Int))
HilbertSpace(items; kernel = k, max_bytes = typemax(Int))
HilbertSpace(points::AbstractVector{<:AbstractVector{<:Real}}; max_bytes = typemax(Int))
HilbertSpace(pts::AbstractVector{<:VPoint}; max_bytes = typemax(Int))

A Hilbert space known only through the squared distances of its input vertices 1:length(items): the points of a dataset, possibly in an infinite-dimensional space, such as the feature space of a kernel. Curves through its vertices (vcurve) are sequences of virtual points (VPoint); geometry on them uses only squared distances, each computed at most once and cached.

The squared distance of two items x, y is

  • dist2(x, y), given directly (the most accurate choice when it can be computed without cancellation: for a Gaussian kernel, -2expm1(-|x - y|^2 / s^2));
  • k(x, x) + k(y, y) - 2k(x, y) for a positive-definite kernel k (clamped at 0; the diagonal is computed once);
  • the Euclidean squared distance, for items that are coordinate vectors;
  • for virtual points of another space, their squared distance there: the points become the input vertices of the new space (re-basing).

The distance function must be pure and thread-safe: threads share the space and may compute an entry concurrently. It must return finite non-negative values, and must come from a Hilbert space (a positive-definite kernel): otherwise the geometry is meaningless.

The cache holds the computed squared distances in blocks of 256 x 256 pairs (512 KB), allocated when first touched. With max_bytes, no blocks are allocated beyond that size; further values are computed without being stored (cache_stats counts them). empty!(S) frees the cache. deepcopy returns the space itself, so morphings copied with deepcopy keep their points in the same space.

A HilbertSpace is a finite metric space (AbsFMS): size(S) and dist(S, i, j).

BasicCompGeometry.VPoint — Type
VPoint(S::HilbertSpace, a, b, t)

The virtual point (1 - t) x_a + t x_b of the space S, on the segment of its input vertices a and b (any two, not only consecutive ones), with t in [0, 1]; 24 bytes, holding a reference to S. vpoint(S, i) is the input vertex i.

The representation is canonical: a < b, and an input vertex has a == b and t == 0. So == and hash agree with geometry for points of the same pair of vertices (two input vertices at distance zero are still different points).

dist, dist_sq and convex_comb take virtual points of one space; so do local_frame, BasicCompGeometry.line_params, BasicCompGeometry.inner_diff and BasicCompGeometry.vscale. A convex combination of two points is representable only if they lie on one segment of two input vertices; otherwise it throws an ArgumentError (re-base the points into a new space with HilbertSpace(pts) first).

BasicCompGeometry.local_frame — Function
local_frame(points::VPoint...) -> NTuple{N, Point{3, Float64}}

The points of one space placed isometrically in ℝ³: the distinct input vertices involved (at most four) are sorted by index, the first is placed at the origin, and the others from the Gram matrix of their differences (polarization of the cached squared distances) by a pivoted Cholesky factorization, with negative pivots (rounding) clamped to 0. Each point is then (1 - t) v_a + t v_b. Euclidean code can run on the result: distances, closest points and inner products in the frame are those of the space, up to rounding (relative to BasicCompGeometry.vscale).

BasicCompGeometry.dist_sq — Method
dist_sq(x::VPoint, y::VPoint)

The squared distance of two virtual points of one space, from the squared distances of the (at most four) input vertices involved: |Σ λ_i x_i|^2 = -Σ_{i<j} λ_i λ_j D_ij^2 for weights summing to zero (the identity needs no distinct vertices), clamped at 0. Points of one pair of vertices give (t - s)^2 D_ab^2. Accuracy: for points at distance δ, with vertices at distance up to D, the absolute error is about ε D^2 / δ (inherent to computing from squared distances).

Virtual arrays

VirtArray.VArray wraps a vector and an index permutation without reordering the original storage. VirtArray.orig_index(array, i) returns the underlying vector index at position i; VirtArray.swap!(array, i, j) exchanges virtual positions.

BasicCompGeometry.VirtArray — Module
VirtArray

Permutation views over a vector (VArray): algorithms reorder the view by swapping entries of a permutation instead of moving the data, and orig_index maps a view position back to the index in the underlying vector.
