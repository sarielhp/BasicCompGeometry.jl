BasicCompGeometry.triangulate_polygon — Method
triangulate_polygon(vertices; kernel=FloatingKernel(), algorithm=:ear_clipping, rng=Random.default_rng()) -> PolygonTriangulation

Triangulate a simple counterclockwise polygon with n >= 3 vertices. Returns a PolygonTriangulation with:

  • result.diagonals: n - 3 distinct internal diagonals as index pairs (i, j) with i < j.
  • result.triangles: n - 2 counterclockwise triangles as index triples (i, j, m).

Supported algorithm options:

  • :ear_clipping (default): Fast ear clipping with reflex-vertex acceleration running in O(n r) time.
  • :seidel: Raimund Seidel's randomized incremental algorithm running in expected O(n log* n) time.

For x-monotone or y-monotone polygons, triangulates in linear time O(n).

Preconditions

  • vertices must form a simple counterclockwise polygon with n >= 3 vertices.

BasicCompGeometry.polygon_kernel — Method
polygon_kernel(poly; kernel=FloatingKernel())

Compute the kernel of a simple counterclockwise polygon $P$, denoted $\mathrm{Ker}(P)$.

The kernel is the set of all points in $P$ from which the entire polygon is visible: $\mathrm{Ker}(P) = \{ q \in P \mid \forall p \in P, \overline{qp} \subset P \}$. It is the intersection of all closed inward halfplanes supported by the directed edges of $P$.

Arguments

  • poly: vertices of a counterclockwise simple polygon, supplied as an AbstractVector{<:Point{2}} or an AbsPntSeq{2}.
  • kernel: computational geometry kernel (FloatingKernel() or ExactKernel()). Default is FloatingKernel().

Returns

  • Vector{Point{2, R}}: vertices of the convex polygon forming the kernel in counterclockwise order, or an empty vector if the polygon has an empty kernel (i.e. is not star-shaped).

Preconditions

  • poly must have at least 3 vertices and be oriented counterclockwise with positive area.
source
BasicCompGeometry.visibility_polygon — Method
visibility_polygon(poly, q; kernel=FloatingKernel())

Compute the star-shaped visibility polygon $\mathrm{Vis}(q, P)$ consisting of all points inside a counterclockwise simple polygon $P$ that are visible from vantage point $q \in P$.

A point $p \in P$ is visible from $q$ if the open line segment between $q$ and $p$ does not intersect the exterior of $P$ or any boundary edge of $P$.

Arguments

  • poly: vertices of a counterclockwise simple polygon, supplied as an AbstractVector{<:Point{2}} or an AbsPntSeq{2}.
  • q: vantage point (Point{2} or 2-element coordinate vector) located in the interior or on the boundary of poly.
  • kernel: computational geometry kernel (FloatingKernel() or ExactKernel()). Default is FloatingKernel(). Under ExactKernel(), rational coordinates and exact arithmetic are used throughout.

Returns

  • Vector{Point{2, R}}: vertices of the star-shaped visibility polygon in counterclockwise order, with collinear intermediate vertices pruned.

Preconditions

  • poly must have at least 3 vertices and be oriented counterclockwise with positive area (as verified by twice_area).
  • q must lie strictly in the interior or on the boundary of poly. An ArgumentError is thrown if q is outside poly.

Examples

using BasicCompGeometry

# U-shaped polygon
p_u = [
    point(0.0, 0.0), point(4.0, 0.0), point(4.0, 4.0), point(3.0, 4.0),
    point(3.0, 1.0), point(1.0, 1.0), point(1.0, 4.0), point(0.0, 4.0)
]

# Query from bottom corridor
vis = visibility_polygon(p_u, point(2.0, 0.5))
length(vis) # 6 vertices
twice_area(vis) # 9.0

BasicCompGeometry.minkowski_sum — Method
minkowski_sum(poly1, poly2; kernel=FloatingKernel(), hull=false)

Compute the Minkowski sum $P \oplus Q = \{ p + q \mid p \in P, q \in Q \}$ of two 2D polygons or geometric shapes.

For two convex polygons with $n$ and $m$ vertices, the Minkowski sum is computed in optimal $O(n + m)$ time by merging the cyclically ordered edge lists by polar angle without quadratic pairwise expansion. The vertices of the resulting convex polygon are returned in counterclockwise order.

If hull=true, computes the convex hull of the Minkowski sum $\mathrm{CH}(P \oplus Q) = \mathrm{CH}(P) \oplus \mathrm{CH}(Q)$ in $O(n \log n + m \log m)$ time, valid for any input polygons (including non-convex polygons). If hull=false (default), both polygons must be convex; otherwise an ArgumentError is thrown. For non-convex polygons without taking the convex hull, see minkowski_sum_decomposition.

Arguments

  • poly1, poly2: convex polygons (as AbstractVector{<:Point{2}} or AbsPntSeq{2}), segments (Segment{2}), or points (Point{2}).
  • kernel: computational geometry kernel (FloatingKernel() or ExactKernel()).
  • hull: whether to compute the convex hull of the Minkowski sum (default false).

Returns

  • Vector{Point{2, R}}: vertices of the Minkowski sum polygon in counterclockwise order. If both inputs are single points, returns a Point{2}. If one input is a point and the other is a segment, returns a Segment{2}.

Examples

sq1 = [point(0.0, 0.0), point(1.0, 0.0), point(1.0, 1.0), point(0.0, 1.0)]
sq2 = [point(0.0, 0.0), point(2.0, 0.0), point(2.0, 2.0), point(0.0, 2.0)]
minkowski_sum(sq1, sq2) # 4 vertices from [0, 0] to [3, 3]

BasicCompGeometry.minkowski_sum_decomposition — Method
minkowski_sum_decomposition(poly1, poly2; kernel=FloatingKernel())

Compute the Minkowski sum decomposition of two simple polygons into convex pieces.

If either polygon is non-convex, it is triangulated into convex triangles using triangulate_polygon. The Minkowski sum of each pair of convex pieces is computed in linear time. Returns a Vector{Vector{Point{2, R}}} containing all convex pieces whose union is the Minkowski sum $P \oplus Q = \bigcup_{i, j} (P_i \oplus Q_j)$.

If both inputs are already convex, returns a 1-element vector containing the single convex Minkowski sum polygon.

Discrete hulls of convex bodies

The discrete hull of a planar convex body $C$ is $\mathrm{CH}(C \cap \mathbb{Z}^2)$. discrete_hull implements the output-sensitive algorithm of Har-Peled (An Output Sensitive Algorithm for Discrete Convex Hulls, CGTA 10, 1998). It reads $C$ only through chord_range and makes $O(|C'| \log \mathrm{diam}(C))$ calls, where $|C'|$ is the number of hull vertices. For a disk of radius $r$ this is $O(r^{2/3} \log r)$.

CallResult

chord_range(C, o, d)nothing if the line o + t*d misses C, else (⌈t_lo⌉, ⌊t_hi⌋)
LatticeDisk(center, radius)Disk with exact rational center and radius; floats are rounded to multiples of 1/den (default 2^16)
ConvexPolygonBody(vertices)Convex polygon with exact rational vertices in counterclockwise order
FloatChordBody(f)Body given by a floating-point chord function f(o, d); exact only up to the rounding of f

discrete_hull_start(C, seed)Lowest-leftmost lattice point of C by unbounded and binary search; needs lattice-connected C ∩ Z²
discrete_hull_columns(C[, xs])Naive $O(r)$ hull of the lowest and highest lattice points on each column
lattice_convex_hull(points)Exact convex hull of integer points

For other bodies, subtype AbsLatticeBody, implement chord_range, and pass either seed (a lattice point of C) or start (a vertex of the hull). The chord_range results determine the hull, so the hull is exact when they are.

BasicCompGeometry.chord_range — Function
chord_range(C::AbsLatticeBody, o::Point2I, d::Point2I)

Intersect C with the line o + t*d (d ≠ 0). Returns nothing when the line misses C; otherwise returns (ceil(t_lo), floor(t_hi)) as Ints, where [t_lo, t_hi] is the closed parameter interval of the chord. The integers in lo:hi are exactly the t with o + t*d ∈ C; the range is empty (lo > hi) when the chord holds no integer parameter.

This is the only access to C used by discrete_hull. Exact implementations make the hull exact.

source
BasicCompGeometry.discrete_hull — Method
discrete_hull(C; seed = nothing, start = nothing) -> Vector{Point2I}

Vertices of the discrete hull ConvexHull(C ∩ Z²) of the planar convex body C, in counterclockwise order starting at the lowest-leftmost vertex (no collinear vertices). Returns an empty vector when C ∩ Z² = ∅.

Implements the output-sensitive algorithm of Har-Peled (1998): O(|C'| log diam(C)) calls to chord_range, where |C'| is the output size. For a disk of radius r this is O(r^(2/3) log r).

The first vertex is found from start (any vertex of the discrete hull), or else from seed (any lattice point of C; requires C ∩ Z² to be lattice-connected) by discrete_hull_start. LatticeDisk and ConvexPolygonBody supply defaults.

BasicCompGeometry.find_edge_direction — Method
find_edge_direction(C, p, L, U)

FindEdgeDirection restricted to the closed cone spanned by the lattice basis (L, U) (det(L, U) = 1, both in one closed quadrant). Returns the primitive lattice vector e in this cone with p + e ∈ C of smallest angle from L, or nothing. Requires p ∈ C.

The search mirrors the Euclidean algorithm on the unknown e: it alternates a ray shooting from L in direction U (column step, even convergents) and from U in direction L (row step, odd convergents). Invariants: (L, U) is a unimodular basis, p + L ∉ C, no feasible vector lies at angle ≤ L, and every feasible vector at angle ≥ U is no better than best. Each pair of steps at least doubles the basis vectors, so O(log diam(C)) chord queries suffice.

BasicCompGeometry.build_rmq — Method
build_rmq(keys; less=isless, backend=:blocked)

Index the one-based vector keys for range-minimum queries under the strict weak order less. Query with range_argmin. Empty input may be indexed but has no valid query.

The default :blocked backend takes O(n) preprocessing time and machine words and answers queries in O(1) comparisons and word operations. The model is a word RAM with constant-time leading_zeros, trailing_zeros and shifts on UInt words (block size is floor(log2 n) <= 63 <= word size); key comparisons are charged to less. No hashing is used. backend=:sparse is the O(n log n) preprocessing/space reference with O(1) queries.

The keys are borrowed, not copied: the caller must keep them (and the order less) unchanged for the lifetime of the index. The index is never mutated by queries.

This module implements an algorithm to find the largest convex subset of a given set of points. The algorithm uses dynamic programming (DP) to compute the longest convex chain between pairs of points and then combines upper and lower chains to form the longest convex polygon.

The running time of the algorithm is O(n^3 log n).
